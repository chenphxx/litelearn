# 数据库设计

## 概述

- 数据库类型: MySQL 9.x 
- 数据库名称: `litelearn` 
- 字符集: `utf8mb4` / `utf8mb4_unicode_ci`(支持中文与 emoji) 
- 存储引擎: InnoDB(支持外键与事务) 
- 作用: 存储代码速查知识库, 包括技术栈与其下的知识点文章 
- 文章采用软删除: `deleted_at` 为空表示正常数据, 非空表示已移入回收站, 回收站中的文章不参与检索与备份导出 

## 表结构

### 技术栈表 `stacks`

```sql
CREATE TABLE IF NOT EXISTS stacks (
    id          INT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '技术栈编号',
    name        VARCHAR(64)   NOT NULL                COMMENT '技术栈名称, 唯一',
    description VARCHAR(255)  NOT NULL DEFAULT ''     COMMENT '技术栈描述',
    created_at  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_stacks_name (name)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci
  COMMENT = '技术栈表';
```

### 文章表 `snippets`

```sql
CREATE TABLE IF NOT EXISTS snippets (
    id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '文章编号, 兼容旧版 number_index',
    stack_id     INT UNSIGNED    NOT NULL                COMMENT '所属技术栈, 外键',
    zh_index     VARCHAR(128)    NOT NULL DEFAULT ''     COMMENT '中文索引',
    en_index     VARCHAR(128)    NOT NULL DEFAULT ''     COMMENT '英文索引',
    content      MEDIUMTEXT      NOT NULL                COMMENT '正文, 以文章形式记录知识点',
    created_at   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP
                                 ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted_at   DATETIME        NULL DEFAULT NULL       COMMENT '删除时间, 非空表示已移入回收站',
    PRIMARY KEY (id),
    KEY idx_snippets_stack_zh (stack_id, zh_index),
    KEY idx_snippets_stack_en (stack_id, en_index),
    KEY idx_snippets_stack_deleted (stack_id, deleted_at),
    CONSTRAINT fk_snippets_stack
        FOREIGN KEY (stack_id) REFERENCES stacks (id) ON DELETE CASCADE
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci
  COMMENT = '文章表';
```

## 字段说明

| 表        | 字段                      | 说明                               |
| -------- | ----------------------- | -------------------------------- |
| stacks   | id                      | 自增主键                             |
| stacks   | name                    | 技术栈名称, 如 `C` / `CPP` / `Rust`    |
| stacks   | description             | 技术栈描述, 可留空                       |
| stacks   | created_at              | 创建时间                             |
| snippets | id                      | 自增主键, 迁移时沿用旧版 `number_index` 的数值 |
| snippets | stack_id                | 所属技术栈, 级联删除                      |
| snippets | zh_index                | 中文索引, 用于检索                       |
| snippets | en_index                | 英文索引, 用于检索                       |
| snippets | content                 | 正文, 以文章形式记录知识点, 类型为 `MEDIUMTEXT`, 旧版代码片段与中文说明合并存放于此字段 |
| snippets | created_at / updated_at | 创建/更新时间, 更新时间自动维护                |
| snippets | deleted_at              | 删除时间, 非空表示已移入回收站, 回收站可还原或彻底删除    |

索引说明: 

- `idx_snippets_stack_zh` 与 `idx_snippets_stack_en` 支撑按技术栈与索引字段的检索 
- `idx_snippets_stack_deleted` 支撑按技术栈过滤未删除文章的查询, 以及回收站列表按删除时间排序 
- 删除技术栈时, 外键 `ON DELETE CASCADE` 会同时删除该技术栈下的全部文章, 包括回收站中的文章 

## 结构迁移

- 应用启动建表后由 `ensure_schema` 检查旧版本数据库缺失的结构, 通过 `information_schema` 查询字段与索引是否存在, 缺失时执行 `ALTER TABLE` 补齐 
- 补齐项包括 `snippets.deleted_at` 字段与 `idx_snippets_stack_deleted` 索引, 使旧库无需手工迁移即可使用回收站 
- 旧库的正文列 `snippets.code_snippet` 在启动时改名为 `content`, `snippets.zh_comment` 字段并入正文后删除: 代码片段在前, 中文说明在后, 中间以一个空行分隔, 中文说明为空时只保留代码片段 
- 正文列类型统一为 `MEDIUMTEXT`: 改名时按 `MEDIUMTEXT` 重建, 已存在但类型不是 `MEDIUMTEXT` 的 `content` 列执行 `MODIFY COLUMN content MEDIUMTEXT` 归一, 避免新旧库字段类型不一致 

## 检索设计

- 输入 `000` 或空字符串: 查询当前范围内(当前技术栈或全部技术栈)的全部数据 
- 字段前缀: `zh:` / `en:` / `content:` 分别限定中文索引, 英文索引与正文, `code:` 为兼容旧用法的别名 
- 输入纯数字(非 `000`): 在模糊匹配之外额外按文章编号 `id` 精确匹配, 兼容旧版按 `number_index` 查询的习惯 
- 输入其它关键词: 对 `zh_index`, `en_index`, `content` 进行 `LIKE '%关键词%'` 模糊匹配 
- 不区分中英文输入, 两种索引字段同时参与匹配 
- 排序支持 `id_asc`(默认) / `id_desc` / `updated_asc` / `updated_desc`, 按更新时间排序时以编号作为次关键字保证顺序稳定 
- 分页使用 `LIMIT` / `OFFSET`, 每页数量默认为 50, 上限为 200, 同时返回符合条件的总数 
- 所有检索均在 `deleted_at IS NULL` 的前提下进行, 回收站中的文章不参与匹配 

## 备份与导入导出

- 应用内 `导出备份` 功能可导出全部数据, 只包含未删除的文章 
- JSON 格式: 包含技术栈与文章的完整结构化数据, 便于长期存档与再次导入 
- CSV 格式: 文章明细的扁平表格数据, 便于用表格软件打开查看, 表头为 `stack_name,id,zh_index,en_index,content,created_at,updated_at` 
- 单文章可通过 `导出 MD` 导出为 Markdown 文件, 内容包含标题, 技术栈, 编号, 索引, 更新时间与代码块 
- 导入旧版备份时, 备份中的 `code_snippet` 与 `zh_comment` 列或字段会按同样的规则并入 `content` 
- 导出文件由 Rust 后端生成, 支持自定义保存位置 
- 应用内 `导入备份` 可将导出的 JSON / CSV 文件重新导入, 导入前显示预览统计, 不修改数据库 
- 导入采用合并方式: 技术栈按名称匹配并自动创建, 文章编号已存在时默认跳过, 开启覆盖后按备份内容更新 
- 导入时可还原备份时的创建/更新时间
