# 架构设计

## 概述

LiteLearn 是一款基于 Tauri 2 的桌面软件, 前端使用原生 JavaScript, 数据库采用 MySQL 

主要功能如下: 

- 按技术栈 (stacks) 归档知识点文章 (snippets), 支持中文索引与英文索引检索 
- 支持按技术栈筛选, 字段限定 (zh: / en: / content:), 排序与分页加载 
- 支持新增, 修改, 删除, 克隆文章, 支持技术栈的新建, 编辑与删除 
- 删除的文章进入回收站, 可还原或彻底删除 
- 正文编辑区基于 CodeMirror 6, 按技术栈自动切换语法高亮, 并支持调整正文字号 
- 支持 JSON / CSV 两种备份导出与合并导入, 导入前可预览并选择是否覆盖 
- 支持将单篇文章导出为 Markdown 文件, 或复制为 Markdown 代码块 
- 内置 SQL 控制台, 默认只读模式, 危险语句执行前二次确认 
- 数据库连接信息可在应用内配置, 支持环境变量覆盖, 顶部实时显示连接状态 
- 支持浅色 / 深色 / 跟随系统三种主题, 记忆窗口尺寸, 侧边栏状态与分栏宽度 

## 技术选型

| 层      | 技术                                     | 说明                          |
| ------ | -------------------------------------- | --------------------------- |
| 前端     | HTML / CSS / 原生 JavaScript (ES Module) | 单页静态骨架, 按职责拆分为多个模块, 不引入前端框架 |
| 代码编辑器  | CodeMirror 6                           | 语法高亮, 行号, 括号匹配, 按技术栈动态加载语言  |
| 前端构建   | Vite 6                                 | 开发服务器与前端产物构建                |
| 桌面框架   | Tauri 2 (Rust)                         | 窗口, WebView 与前后端 IPC        |
| 后端     | Rust 2021 edition                      | 业务逻辑, 数据库访问与备份文件读写          |
| 数据库    | MySQL 9.x                              | 通过 mysql crate 访问, 使用连接池    |
| 文件对话框  | tauri-plugin-dialog 2                  | 备份文件的打开与保存路径选择              |
| 打包     | Tauri NSIS                             | Windows 安装包                 |

职责边界如下: 

- 所有数据操作均通过 Tauri Command 完成 
- 前端按界面职责拆分模块, 模块之间不直接互相调用, 统一通过 `state` 与 `actions` 注册表协作 
- 后端集中负责 SQL 构造, 参数校验, 数据读写与备份文件读写 
- 前后端通过 serde 序列化的结构体交换数据, 如 `StackInfo`, `Snippet`, `SearchResult`, `DeletedSnippet`, `SqlResult`, `ImportSummary`

## 前端实现

### 模块划分

| 模块               | 职责                                             |
| ---------------- | ---------------------------------------------- |
| `main.js`        | 按顺序调用各模块初始化函数, 装配动作与快捷键, 处理启动时的连接检查与首次检索        |
| `api.js`         | 封装全部 `invoke` 命令与 `save` / `open` 文件对话框, 其它模块不直接调用 Tauri API |
| `state.js`       | 导出全局 `state` 与 `actions` 注册表, 注册表由 `main.js` 在启动时填充 |
| `ui.js`          | 缓存 DOM 引用, 提供图标, 转义, 复制, 轻提示, 弹窗管理, 更多菜单与主题切换   |
| `editor.js`      | 创建正文 CodeMirror 编辑器, 维护语言映射, 主题高亮与正文字号         |
| `stacks.js`      | 渲染侧边栏技术栈列表, 处理技术栈的新建, 编辑与删除                    |
| `results.js`     | 执行检索, 渲染表格, 骨架屏, 关键词高亮, 排序与加载更多                |
| `detail.js`      | 打开文章, 编辑索引, 未保存保护, 保存, 删除, 复制, 克隆与 Markdown 导出 |
| `snippet-form.js` | 新增数据弹窗, 复用为克隆文章                               |
| `history.js`     | 搜索历史与最近打开记录, 存放于 `localStorage`                 |
| `recycle.js`     | 回收站列表, 还原, 彻底删除与清空                             |
| `backup.js`      | 备份导出, 导入预览, 覆盖开关与窗口拖放导入                        |
| `sql.js`         | SQL 执行, 只读模式, 危险语句确认与执行历史                      |
| `connection.js`  | 连接状态刷新与数据库设置弹窗                                 |

### 页面与弹窗

- `index.html` 定义顶部工具栏, 左侧技术栈侧边栏, 中间结果表格, 右侧详情编辑区与底部状态栏, 以及新增数据, 技术栈编辑, 设置, 导出, 导入, SQL 控制台, 回收站, 历史记录与确认等 `dialog` 弹窗 
- 界面元素统一通过 `ui.js` 的 `ui` 对象按编号获取, 模块不重复查询 DOM 
- 模态弹窗基于原生 `<dialog>` 与 `showModal()` 实现, `show_dialog` 与 `show_choice` 在打开前关闭其它已打开的弹窗, 避免多个模态弹窗叠加 
- 弹窗支持鼠标拖动与缩放: `enable_drag` 绑定标题栏手柄, `enable_resize` 绑定右下角手柄, 位置与尺寸记录在 `localStorage` 并在下次打开时恢复, 恢复时忽略无效记录并按视口范围校正 
- 详情区宽度由结果区与详情区之间的分隔条控制, 拖动结果写入 `litelearn-detail-width`, 左侧技术栈侧边栏可折叠, 折叠状态写入 `litelearn-sidebar-collapsed` 

### 状态管理

前端不引入状态管理库, `state.js` 维护单一状态对象, 各模块读写后驱动界面重绘 

| 字段                 | 说明                     |
| ------------------ | ---------------------- |
| `stacks`           | 技术栈列表缓存                |
| `currentStackId`   | 当前技术栈编号, `null` 表示全部技术栈 |
| `keyword`          | 当前搜索关键词                |
| `sort`             | 排序方式, 默认 `id_asc`       |
| `rows` / `total`   | 当前结果列表与结果总数            |
| `limit`            | 每页数量, 默认 50            |
| `currentSnippetId` | 当前打开的文章编号              |
| `snapshot`         | 打开文章时的内容快照, 用于判断未保存修改   |
| `connected`        | 数据库连接状态                |
| `sqlReadonly`      | SQL 控制台只读模式            |
| `sidebarCollapsed` | 侧边栏折叠状态                |

模块之间的调用通过 `actions` 注册表解耦, 例如 `open_snippet`, `reload_results`, `reload_stacks`, `select_stack`, `confirm_leave` 等, 均由 `main.js` 在初始化阶段装配 

### 编辑器

- 正文以文章形式记录在单个字段中, 详情区使用单个 CodeMirror 6 实例, 挂载在 `#content-editor` 容器上 
- 编辑器集成 `basicSetup` 与 `indentWithTab`, 支持行号, 括号匹配, 自动换行与 Tab 缩进 
- 技术栈名称经 `LANGUAGE_TABLE` 映射为 CodeMirror 语言, 如 `C` / `C++` / `Python` / `Rust` / `SQL` 等, 打开文章时按技术栈动态加载语言包并重配置高亮 
- 主题变化时通过 Compartment 重新配置语法配色, 深色使用 oneDark 配色, 浅色使用默认配色 
- 程序化写入内容时通过抑制标记避免触发未保存状态 
- 正文字号由 CSS 变量 `--content-font-size` 控制, 作用于编辑器与行号: `A-` / `A+` 按钮每次调整 1px, 范围 11 至 24, 默认 13, 达到边界时对应按钮禁用, 取值保存在 `litelearn-editor-font-size`, 启动时恢复 

- 详情区展示文章编号, 技术栈, 创建时间, 更新时间与正文行数, 并提供复制, 复制 MD, 导出 MD, 克隆与保存操作 
### 检索与结果展示

- 检索参数包含技术栈, 关键词, 排序, 偏移与数量, 一次请求同时返回当前页数据与总数 
- 结果表格展示编号, 技术栈 (全部技术栈时显示), 中文索引, 英文索引与更新时间 
- 表头支持按编号与更新时间切换升序 / 降序, 关键词命中部分使用 `<mark>` 高亮 
- 检索过程中显示骨架屏, 无数据与出错时显示空态并提供可执行按钮, 结果超过一页时通过 `加载更多` 追加下一页 
- 过期响应通过请求序号丢弃, 避免快速切换时旧结果覆盖新结果 

### 未保存保护

- 打开文章时记录 `snapshot`, 正文内容或索引输入与快照不一致时视为存在未保存修改, 编号旁显示标记 
- 切换文章, 切换技术栈或删除前调用 `confirm_leave`, 弹出 `保存并继续` / `放弃修改` / `取消` 三种选择 
- `Ctrl+S` 保存当前文章, `Ctrl+F` 聚焦搜索框, `Ctrl+N` 新增数据, `Ctrl+K` 打开 SQL 控制台 

### 主题与本地存储

- 主题: `apply_theme` 在 `<html>` 上设置 `data-theme`, 样式表通过 `:root` 与 `[data-theme="dark"]` 两组 CSS 变量切换配色, 支持 `system` / `light` / `dark` 三种模式, 跟随系统时监听系统主题变化 
- 本地存储键: `litelearn-theme` 主题, `litelearn-window-size` 窗口尺寸, `litelearn-sidebar-collapsed` 侧边栏折叠, `litelearn-detail-width` 详情区宽度, `litelearn-dialog-bounds` 弹窗位置尺寸, `litelearn-search-history` 搜索历史, `litelearn-recent-snippets` 最近打开, `litelearn-sql-history` SQL 历史, `litelearn-sql-readonly` 只读模式, `litelearn-editor-font-size` 正文字号 
- 提示: `show_status` 在底部状态栏显示临时消息, `toast` 在右下角显示带类型与可选撤销按钮的轻提示 

### 初始化流程

`init()` 依次执行主题初始化, 弹窗布局绑定, 菜单与图标初始化, 编辑器创建, 各模块事件绑定, 动作装配, 侧边栏与分隔条初始化, 快捷键绑定, 随后恢复窗口尺寸并加载技术栈, 最后检查数据库连接: 连接成功时执行一次检索, 失败时提示并打开设置弹窗 

## 后端实现

### 模块划分

| 模块            | 职责                                                     |
| ------------- | ------------------------------------------------------ |
| `main.rs`     | 程序入口, 调用 `litelearn_lib::run()`, 发布版本下隐藏 Windows 控制台窗口 |
| `lib.rs`      | 应用装配: 加载配置, 注册 `AppState`, 初始化 dialog 插件, 注册全部命令       |
| `models.rs`   | 前后端交换的数据结构定义                                           |
| `config.rs`   | 数据库配置的默认值, `config.json` 读写与环境变量覆盖                     |
| `db.rs`       | 应用状态与连接池管理, 数据库与表结构自动初始化                               |
| `backup.rs`   | 备份解析, 导入计划与执行, JSON / CSV 导出, 单文章 Markdown 生成           |
| `commands.rs` | 全部 Tauri 命令: 检索, 增删改, 回收站, 备份, 配置管理与 SQL 控制台            |

### 应用状态与连接池

- `lib.rs` 在 `setup` 阶段读取配置并调用 `app.manage(AppState::new(config))` 注册全局状态 
- `AppState` 包含 `config: Mutex<DbConfig>` 与 `pool: Mutex<Option<Pool>>` 两个字段 
- 连接池为懒加载: 首次执行数据库命令时由 `get_pool` 按当前配置创建, 之后复用 
- 设置保存成功后更新内存配置并调用 `reset_pool`, 使下一次操作按新配置重新建池, 无需重启应用 

### 数据库与表结构初始化

`create_pool` 分两步完成初始化: 

1. 先以不指定数据库的连接访问服务器, 执行 `CREATE DATABASE IF NOT EXISTS`, 字符集为 `utf8mb4`, 排序规则为 `utf8mb4_unicode_ci` 
2. 再连接目标数据库, 执行 `stacks` 与 `snippets` 的 `CREATE TABLE IF NOT EXISTS`, 随后由 `ensure_schema` 检查旧库缺失的字段与索引并自动补齐 

`ensure_schema` 通过 `information_schema` 检查 `snippets` 的字段与索引: 正文列旧名 `code_snippet` 首次运行改名为 `content` 并按 `MEDIUMTEXT` 重建, 已存在但类型不是 `MEDIUMTEXT` 的 `content` 列执行 `MODIFY COLUMN` 归一, 旧字段 `zh_comment` 并入正文后删除, 缺失的 `deleted_at` 字段与 `idx_snippets_stack_deleted` 索引自动补齐, 使旧版本数据库无需手工迁移即可使用当前功能

### 检索实现

`search_snippets` 的查询条件与排序均由参数拼接占位符, 不直接拼接用户输入: 

- 固定条件为 `deleted_at IS NULL`, 回收站中的文章不参与检索 
- `stack_id` 为空时检索全部技术栈, 否则追加 `stack_id = ?` 
- 关键词前缀 `zh:` / `en:` / `content:` 分别限定中文索引, 英文索引与正文, 无前缀时三个字段以 `OR` 组合, `code:` 为兼容旧用法的别名 
- 关键词为空或等于 `000`: 查询当前范围内的全部文章 
- 无前缀的纯数字关键词: 在模糊匹配之外额外匹配 `id = ?` 
- 排序支持 `id_asc` / `id_desc` / `updated_asc` / `updated_desc`, 更新时间排序时以编号作为次关键字保证顺序稳定 
- 分页使用 `LIMIT ? OFFSET ?`, 每页数量默认为 50, 上限为 200 
- 总数与当前页数据分两次查询, 返回 `SearchResult` 

### 写入校验

- 新建与修改技术栈: 名称去空格后不能为空且不超过 64 个字符, 重名由唯一键拦截并转换为 `技术栈已存在` 
- 新增文章: 正文不能为空, 中文索引与英文索引至少填写一项 
- 修改文章: 按主键更新四个字段, 仅允许更新未删除的文章, `updated_at` 由数据库的 `ON UPDATE CURRENT_TIMESTAMP` 自动维护 
- 删除文章: 置 `deleted_at` 为当前时间, 为软删除, 数据仍保留在表中 
- 删除技术栈: 按主键删除, 外键 `ON DELETE CASCADE` 会同时删除其下文章, 前端在执行前给出不可恢复的确认 

### 回收站

- `list_deleted_snippets` 关联技术栈表返回文章编号, 技术栈名称, 中英文索引与删除时间, 按删除时间倒序 
- `restore_snippet` 将 `deleted_at` 置空, 文章重新参与检索 
- `purge_snippet` 与 `purge_all_deleted` 执行物理删除, 操作不可恢复 
- 前端删除文章后提供 `撤销` 轻提示, 直接调用还原命令 

### 备份导出

- 校验格式仅支持 `json` 与 `csv`, 保存路径不能为空 
- 一次性读取全部技术栈与未删除文章, 由 Rust 直接写入目标文件, 不经过前端 
- JSON 结构为 `{ exported_at, stacks, snippets }`, `exported_at` 取数据库服务器的当前时间 
- CSV 表头为 `stack_name,id,zh_index,en_index,content,created_at,updated_at`, 技术栈编号映射为名称, 字段包含逗号, 引号或换行时使用双引号包裹并转义, 行分隔符为 `\r\n` 
- 返回 `ExportSummary`, 包含导出的技术栈数与文章数 
- 单篇文章导出由 `export_snippet_markdown` 生成标题, 技术栈, 编号, 英文索引, 更新时间与代码块, 代码块语言标记由前端按技术栈传入 

### 备份导入

- 校验格式与路径后读取整个备份文件, 解析为 `ParsedStack` 与 `ParsedSnippet` 列表 
- 旧版备份中的 `code_snippet` 与 `zh_comment` 字段在解析时并入正文字段, 规则与数据库迁移一致 
- `plan_import` 生成导入计划: 技术栈按名称匹配, 不存在时加入待创建列表; 文章编号已存在时按 `overwrite` 决定覆盖更新或跳过; 缺少技术栈名称的文章直接跳过 
- 预览与执行共用同一份计划, 预览只统计数量, 不写入数据库, 因此预览结果与实际导入一致 
- JSON: 先建立备份中的技术栈编号到名称的映射, 再逐个确保技术栈存在并插入文章 
- CSV: 跳过表头后按列顺序解析, 字段数不足时返回错误并给出行号 
- 时间字段按 `YYYY-MM-DD HH:MM:SS` 解析还原, 解析失败或为空时写入 `NULL`, 由数据库默认值填充 
- 返回 `ImportSummary`, 包含新建技术栈数, 已存在技术栈数, 新增文章数, 覆盖文章数与跳过文章数 
- 前端在导入前展示预览统计, 覆盖开关默认关闭, 关闭时重复导入保持幂等 

### SQL 控制台

- `analyze_sql` 判断语句是否只读以及是否需要二次确认, 只读语句包括 `SELECT` / `SHOW` / `DESC` / `DESCRIBE` / `EXPLAIN` / `WITH` 
- 危险语句包括 `DROP` / `TRUNCATE` / `ALTER` / `RENAME` / `GRANT` / `REVOKE`, 以及不带 `WHERE` 的 `DELETE` 与 `UPDATE`, 前端执行前弹出确认 
- `execute_sql` 接收 `readonly` 参数, 只读模式下非查询语句直接返回错误, 该模式默认开启并记录在本地 
- 查询语句返回列名与数据行, 写语句返回受影响行数, 结果均以文本形式回传, 前端表格最多渲染 200 行 
- 执行历史保存在本地, 最多 10 条, 点击可回填语句, 单条历史可删除, 也可一键清空 

## 配置管理

配置优先级为 内置默认值 < `config.json` < 环境变量, 环境变量仅覆盖已设置的项 

| 配置项           | 默认值         | 环境变量                    |
| ------------- | ----------- | ----------------------- |
| 数据库地址 host    | `127.0.0.1` | `LITELEARN_DB_HOST`     |
| 端口 port       | `3306`      | `LITELEARN_DB_PORT`     |
| 用户名 user      | `root`      | `LITELEARN_DB_USER`     |
| 密码 password   | 空           | `LITELEARN_DB_PASSWORD` |
| 数据库名 database | `litelearn` | `LITELEARN_DB_NAME`     |

- 配置文件位于系统应用配置目录下的 `config.json`, Windows 下为 `%APPDATA%/com.litelearn.app/config.json` 
- 源码与文档不提供默认密码, 密码由应用内设置或环境变量提供 
- 保存流程: 前端读取表单后调用 `save_config`, 后端先校验配置, 再按新配置建池并连接一次以确认可用, 随后写入配置文件, 更新内存状态并重置连接池 
- 数据库名会被拼入 `CREATE DATABASE` 语句, 因此单独校验并禁止反引号, 分号与单双引号等非法字符 

## 安全约束

- 所有数据读写使用参数化查询, 不拼接用户输入 
- 数据库名作为标识符无法参数化, 通过非法字符校验规避注入风险 
- 前端能力通过 `src-tauri/capabilities/default.json` 限制, 默认仅开放 `core:default` 与 `dialog:default` 
- 备份导入默认跳过已存在的文章编号, 只有显式开启覆盖时才会更新数据库中的现有内容 
- SQL 控制台默认只读, 关闭只读模式仍需对危险语句二次确认, 写操作在确认后才会执行 

## 构建与运行

- 开发: 执行 `npm install` 安装依赖, 执行 `npm run tauri dev` 启动, Vite 固定监听 1420 端口且 `strictPort` 为真, Tauri 窗口加载 `http://localhost:1420` 
- 构建: 执行 `npm run tauri build` 先运行 `npm run build` 生成 `dist/`, 再由 Tauri 打包为 NSIS 安装包, 输出于 `src-tauri/target/release/bundle/` 
- 窗口默认 1280x800, 最小 960x640, 启动时居中, 启动后按上次记录的尺寸恢复 
- Vite 构建目标为 `es2021`, 关闭代码压缩与 sourcemap 
- 前端依赖 CodeMirror 6 与 `@tauri-apps/api`, `@tauri-apps/plugin-dialog`, 由 `package.json` 管理 

## 测试

- 后端单元测试位于 `db.rs` 与 `commands.rs` 的 `#[cfg(test)]` 模块: `test_legacy_schema_migration` 覆盖旧库正文列改名, 正文合并与 `content` 列类型归一, `test_import_round_trip` 覆盖 JSON 导入, 预览不写入, 重复导入幂等, 覆盖导入, 时间还原, 软删除语义以及 CSV 引号与逗号字段解析 
- 上述测试默认跳过, 需同时设置 `LITELEARN_RUN_DB_TEST=1` 与 `LITELEARN_DB_PASSWORD`, 分别在 `litelearn_migration_test` 与 `litelearn_test` 两个独立数据库中执行, 结束后自动删除对应数据库 
- 前端暂无自动化测试, 依赖 `npm run build` 检查构建与手工验证界面流程 

## 扩展指引

- 新增后端命令: 在 `commands.rs` 中实现 `#[tauri::command]` 函数, 在 `lib.rs` 的 `invoke_handler` 中注册, 前端在 `api.js` 中补充封装 
- 新增数据表或字段: 同步修改 `db.rs` 中的建表语句与 `ensure_schema`, 并更新 `docs/数据库设计.md` 
- 新增界面交互: 在 `index.html` 定义元素并在 `ui.js` 中登记引用, 事件绑定放在对应职责模块, 跨模块调用通过 `actions` 注册表补充动作 
- 功能行为或数据库结构变化时, 同步更新 `docs/` 下对应文档与 `CHANGELOG.md`
