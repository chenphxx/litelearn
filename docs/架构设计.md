# LiteLearn 架构设计文档

> 本文档位于 `docs/` 目录, 用于说明 LiteLearn 的整体架构与实现方法, 数据库结构见 `docs/数据库设计.md` 

## 概述

LiteLearn 是一款基于 Tauri 2 的桌面代码速查知识库, 前端使用原生 HTML / CSS / JavaScript, 后端使用 Rust, 数据存储于 MySQL 

主要能力如下: 

- 按技术栈 (stacks) 归档代码片段 (snippets), 支持中文索引与英文索引检索 
- 支持模糊检索与编号精确检索, 输入 `000` 或留空可查看当前技术栈全部数据 
- 支持新增, 修改, 删除代码片段, 支持新建技术栈 
- 支持 JSON / CSV 两种备份导出与合并导入 
- 内置 SQL 控制台, 可手动执行 SQL 语句 
- 数据库连接信息可在应用内配置, 支持环境变量覆盖 
- 支持深色 / 浅色主题切换, 主题偏好保存在本地 

## 技术选型

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | HTML / CSS / 原生 JavaScript (ES Module) | 单页静态骨架, 不引入前端框架 |
| 前端构建 | Vite 6 | 开发服务器与前端产物构建 |
| 桌面框架 | Tauri 2 (Rust) | 窗口, WebView 与前后端 IPC |
| 后端 | Rust 2021 edition | 业务逻辑, 数据库访问与备份文件读写 |
| 数据库 | MySQL 9.x | 通过 mysql crate 28 访问, 使用连接池 |
| 文件对话框 | tauri-plugin-dialog 2 | 备份文件的打开与保存路径选择 |
| 打包 | Tauri NSIS | Windows 安装包 |

## 总体架构

```text
前端 (WebView)
  index.html      静态骨架: 工具栏 / 结果列表 / 详情编辑 / 弹窗
  src/main.js     交互逻辑: 状态缓存, 事件绑定, invoke 调用
  src/styles.css  样式与主题变量 (:root / [data-theme="dark"])
        |
        | Tauri IPC (invoke / command)
        v
后端 (Rust)
  lib.rs          应用装配: 加载配置, 注册全局状态与全部命令
  config.rs       数据库配置: 默认值, config.json 读写, 环境变量覆盖
  db.rs           连接管理: 应用状态, 连接池懒加载与重置, 建库建表
  commands.rs     业务命令: 检索 / 增删改 / 备份导入导出 / SQL 控制台
        |
        | mysql crate (连接池与参数化查询)
        v
MySQL 9.x (stacks / snippets 两张表)
```

职责边界如下: 

- 前端不直接访问数据库, 不拼接 SQL, 所有数据操作均通过 Tauri Command 完成 
- 后端集中负责 SQL 构造, 参数校验, 数据读写与备份文件读写, 前端只负责展示与交互 
- 前后端通过 serde 序列化的结构体交换数据, 如 `StackInfo`, `Snippet`, `SqlResult`, `ImportSummary`

## 前端实现

### 页面与弹窗

- `index.html` 一次性定义工具栏, 左侧结果表格, 右侧代码与说明编辑区, 底部状态栏, 以及新增数据, 新建技术栈, 设置, 导出, 导入, SQL 控制台, 确认等 `dialog` 弹窗 
- 模态弹窗基于原生 `<dialog>` 与 `showModal()` 实现, `show_dialog` 与 `show_confirm` 在打开前关闭其它已打开的弹窗, 避免多个模态弹窗叠加 
- 弹窗支持鼠标拖动与缩放: `enable_drag` 绑定标题栏手柄, `enable_resize` 绑定右下角手柄, 两者均基于 pointer 事件并受最小尺寸约束 

### 状态管理

前端不引入状态管理库, 使用模块级变量缓存界面状态 

| 变量 | 说明 |
| --- | --- |
| `currentStackId` | 当前选中的技术栈编号 |
| `currentSnippetId` | 当前选中的片段编号 |
| `snippetRows` | 当前搜索结果缓存 |
| `stacks` | 技术栈列表缓存 |

- 切换技术栈或执行检索后刷新 `snippetRows` 并重绘结果表格 
- 点击结果行时按编号在缓存中定位数据, 填充右侧编辑区 
- 保存与删除成功后重新执行一次检索, 保持界面与数据库一致 

### 与后端通信

- 统一使用 `@tauri-apps/api/core` 的 `invoke` 调用后端命令, 命令名与 `lib.rs` 中注册的名称一致 
- 参数以对象形式传入, 前端使用驼峰命名(如 `stackId`), Tauri 负责映射到后端的下划线命名参数(如 `stack_id`) 
- 后端错误以 `Err(String)` 返回, 前端捕获后写入底部状态栏或弹窗的状态区域 
- 文件路径选择使用 `@tauri-apps/plugin-dialog` 的 `save` 与 `open`, 文件内容读写仍在后端完成 

### 主题与提示

- 主题: `apply_theme` 在 `<html>` 元素上设置 `data-theme` 属性, 样式表通过 `:root` 与 `[data-theme="dark"]` 两组 CSS 变量切换配色, 偏好写入 `localStorage` 的 `litelearn-theme`, 启动时由 `init_theme` 读取 
- 提示: `show_status` 在底部状态栏显示临时消息, 复制, 保存与导入导出等操作结果均通过状态栏反馈 

### 初始化流程

`init()` 依次执行 `init_theme()` 应用主题, `bind_events()` 绑定全部事件, `load_stacks()` 拉取技术栈并填充下拉框, 若已有选中的技术栈则自动执行一次检索 

## 后端实现

### 模块划分

| 模块 | 职责 |
| --- | --- |
| `main.rs` | 程序入口, 调用 `litelearn_lib::run()`, 发布版本下隐藏 Windows 控制台窗口 |
| `lib.rs` | 应用装配: 加载配置, 注册 `AppState`, 初始化 dialog 插件, 注册全部命令 |
| `config.rs` | 数据库配置的默认值, `config.json` 读写与环境变量覆盖 |
| `db.rs` | 应用状态与连接池管理, 数据库与表结构自动初始化 |
| `commands.rs` | 全部 Tauri 命令: 检索, 增删改, 备份导入导出, 配置管理与 SQL 控制台 |

### 应用状态与连接池

- `lib.rs` 在 `setup` 阶段读取配置并调用 `app.manage(AppState::new(config))` 注册全局状态 
- `AppState` 包含 `config: Mutex<DbConfig>` 与 `pool: Mutex<Option<Pool>>` 两个字段 
- 连接池为懒加载: 首次执行数据库命令时由 `get_pool` 按当前配置创建, 之后复用 
- 设置保存成功后更新内存配置并调用 `reset_pool`, 使下一次操作按新配置重新建池, 无需重启应用 

### 数据库与表结构初始化

`create_pool` 分两步完成初始化: 

1. 先以不指定数据库的连接访问服务器, 执行 `CREATE DATABASE IF NOT EXISTS`, 字符集为 `utf8mb4`, 排序规则为 `utf8mb4_unicode_ci` 
2. 再连接目标数据库, 执行 `stacks` 与 `snippets` 的 `CREATE TABLE IF NOT EXISTS` 

因此首次运行只需 MySQL 服务可用且账号具备建库权限, 应用会自动补齐缺失的数据库与表结构, 并且不会覆盖已有数据 

### 命令清单

| 命令 | 参数 | 返回 | 职责 |
| --- | --- | --- | --- |
| `list_stacks` | 无 | `Vec<StackInfo>` | 查询技术栈列表及各自的片段数量 |
| `search_snippets` | `stack_id`, `keyword` | `Vec<Snippet>` | 按技术栈与关键词检索片段 |
| `create_stack` | `name`, `description` | `u64` | 新建技术栈, 名称唯一 |
| `add_snippet` | `stack_id`, `zh_index`, `en_index`, `code_snippet`, `zh_comment` | `u64` | 新增片段 |
| `update_snippet` | `id`, `zh_index`, `en_index`, `code_snippet`, `zh_comment` | `u64` | 更新片段, 返回受影响行数 |
| `delete_snippet` | `id` | `u64` | 删除片段 |
| `export_backup` | `format`, `path` | `ExportSummary` | 导出 JSON / CSV 备份 |
| `import_backup` | `format`, `path` | `ImportSummary` | 导入备份并合并写入 |
| `get_config` | 无 | `DbConfig` | 读取当前数据库配置 |
| `save_config` | `config` | 无 | 校验并测试连接后保存配置 |
| `test_connection` | `config` | `String` | 测试连接并返回 MySQL 版本号 |
| `execute_sql` | `sql` | `SqlResult` | 执行 SQL, 返回列名, 数据行与受影响行数 |

全部命令在 `lib.rs` 的 `invoke_handler` 中通过 `generate_handler!` 注册, 新增命令时必须同步注册 

### 检索实现

`search_snippets` 在 `stack_id` 条件之上按关键词拼接不同条件: 

- 关键词为空或等于 `000`: 查询该技术栈的全部片段, 按 `id` 升序 
- 关键词可解析为数字: 在模糊匹配之外额外匹配 `id = ?` 
- 其它关键词: 对 `zh_index`, `en_index`, `code_snippet`, `zh_comment` 做 `LIKE '%关键词%'` 匹配, 四个条件以 `OR` 组合 

所有用户输入均通过占位符参数传递, 不做字符串拼接 

### 写入校验

- 新建技术栈: 名称去空格后不能为空且不超过 64 个字符, 重名由唯一键拦截并转换为 `技术栈已存在` 
- 新增片段: 代码片段不能为空, 中文索引与英文索引至少填写一项 
- 修改片段: 按主键更新四个字段, `updated_at` 由数据库的 `ON UPDATE CURRENT_TIMESTAMP` 自动维护 
- 删除片段: 按主键删除, 当前未提供删除技术栈的命令 

### 备份导出

- 校验格式仅支持 `json` 与 `csv`, 保存路径不能为空 
- 一次性读取全部技术栈与片段, 由 Rust 直接写入目标文件, 不经过前端 
- JSON 结构为 `{ exported_at, stacks, snippets }`, `exported_at` 取数据库服务器的当前时间 
- CSV 表头为 `stack_name,id,zh_index,en_index,code_snippet,zh_comment,created_at,updated_at`, 技术栈编号映射为名称, 字段包含逗号, 引号或换行时使用双引号包裹并转义, 行分隔符为 `\r\n` 
- 返回 `ExportSummary`, 包含导出的技术栈数与片段数 

### 备份导入

- 校验格式与路径后读取整个备份文件, 交由 `import_json` 或 `import_csv` 处理 
- 合并策略: 技术栈按名称匹配, 不存在时自动创建, 片段编号已存在时跳过, 不覆盖已有数据, 因此重复导入是幂等的 
- JSON: 先建立备份中的技术栈编号到名称的映射, 再逐个确保技术栈存在并插入片段 
- CSV: 跳过表头后按列顺序解析, 字段数不足时返回错误并给出行号 
- 时间字段按 `YYYY-MM-DD HH:MM:SS` 解析还原, 解析失败或为空时写入 `NULL`, 由数据库默认值填充 
- 返回 `ImportSummary`, 包含新建技术栈数, 已存在技术栈数, 导入片段数与跳过片段数 

### SQL 控制台

- `execute_sql` 直接执行前端传入的 SQL, 空语句返回错误 
- 查询语句返回列名与数据行, 写语句返回受影响行数, 结果均以文本形式回传 
- 该功能面向开发者调试, 未限制语句类型, 可执行任意 SQL, 存在误操作风险 

## 配置管理

配置优先级为 内置默认值 < `config.json` < 环境变量, 环境变量仅覆盖已设置的项 

| 配置项 | 默认值 | 环境变量 |
| --- | --- | --- |
| 数据库地址 host | `127.0.0.1` | `LITELEARN_DB_HOST` |
| 端口 port | `3306` | `LITELEARN_DB_PORT` |
| 用户名 user | `root` | `LITELEARN_DB_USER` |
| 密码 password | 空 | `LITELEARN_DB_PASSWORD` |
| 数据库名 database | `litelearn` | `LITELEARN_DB_NAME` |

- 配置文件位于系统应用配置目录下的 `config.json`, Windows 下为 `%APPDATA%/com.litelearn.app/config.json` 
- 源码与文档不提供默认密码, 密码由应用内设置或环境变量提供 
- 保存流程: 前端读取表单后调用 `save_config`, 后端先校验配置, 再按新配置建池并连接一次以确认可用, 随后写入配置文件, 更新内存状态并重置连接池 
- 数据库名会被拼入 `CREATE DATABASE` 语句, 因此单独校验并禁止反引号, 分号与单双引号等非法字符 

## 安全约束

- 所有数据读写使用参数化查询, 不拼接用户输入 
- 数据库名作为标识符无法参数化, 通过非法字符校验规避注入风险 
- 前端能力通过 `src-tauri/capabilities/default.json` 限制, 默认仅开放 `core:default` 与 `dialog:default` 
- 备份导入按编号跳过已存在的数据, 不会覆盖数据库中的现有内容 
- SQL 控制台不受额外限制, 属于开发者工具, 使用前需明确操作对象 

## 构建与运行

- 开发: 执行 `npm install` 安装依赖, 执行 `npm run tauri dev` 启动, Vite 固定监听 1420 端口且 `strictPort` 为真, Tauri 窗口加载 `http://localhost:1420` 
- 构建: 执行 `npm run tauri build` 先运行 `npm run build` 生成 `dist/`, 再由 Tauri 打包为 NSIS 安装包, 输出于 `src-tauri/target/release/bundle/` 
- 窗口默认 1280x800, 最小 960x640, 启动时居中 
- Vite 构建目标为 `es2021`, 关闭代码压缩与 sourcemap 

## 测试

- 后端单元测试位于 `commands.rs` 的 `#[cfg(test)]` 模块, `test_import_round_trip` 覆盖 JSON 导入, 重复导入幂等, 时间还原以及 CSV 引号与逗号字段解析 
- 该测试默认跳过, 需同时设置 `LITELEARN_RUN_DB_TEST=1` 与 `LITELEARN_DB_PASSWORD`, 使用本机 MySQL 上独立的 `litelearn_test` 数据库, 结束后自动删除该库 
- 前端暂无自动化测试, 依赖手工验证界面流程 

## 扩展指引

- 新增后端命令: 在 `commands.rs` 中实现 `#[tauri::command]` 函数, 在 `lib.rs` 的 `invoke_handler` 中注册, 前端通过 `invoke` 调用 
- 新增数据表或字段: 同步修改 `db.rs` 中的建表语句与 `docs/数据库设计.md` 
- 新增界面交互: 在 `index.html` 定义元素, 在 `main.js` 的 `bind_events` 中绑定事件 
- 功能行为或数据库结构变化时, 同步更新 `docs/` 下对应文档与 `CHANGELOG.md`
